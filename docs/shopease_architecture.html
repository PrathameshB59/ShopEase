1. FINAL PRODUCTION ARCHITECTURE

Development Mode (HTTP)

User Browser (http://localhost:8000, :8080, :9000) | Django runserver (DEBUG=True, serves static files) | +---------+---------+ | | | Customer Admin Docs :8000 :8080 :9000 | | | +----+----+----+----+ | | MySQL MongoDB Atlas (WSL) (Cloud) | Redis (WSL :6379) | Celery Worker

Production Mode (HTTPS via Ngrok)

User Browser / Mobile / Internet | Ngrok (HTTPS tunnel) | https://xxx.ngrok-free.dev | Nginx (WSL - Reverse Proxy + Static Files) Listens on: 80, 8080, 9000 | +----------+----------+ | | | Gunicorn Gunicorn Gunicorn :8001 :8081 :9001 (Customer) (Admin) (Docs) | | | +-----+----+-----+---+ | | MySQL MongoDB Atlas (WSL) (Cloud) | Redis (WSL :6379) | Celery Worker
Key Difference: In development, Django serves static files directly. In production, Nginx serves static files and proxies dynamic requests to Gunicorn.

2. WHO STORES WHAT?

MySQL (Main Database - Structured)

Used by Django ORM

  • Users, Products, Categories, Product Images
  • Reviews, Cart, Orders, Payments

Needs: Relationships, Transactions, Data Integrity

MongoDB Atlas (Secondary - Flexible)

Used via PyMongo

  • User activity logs, Recently viewed products
  • Search history, User preferences
  • Product extra specifications, Analytics events

Redis (Fast Memory - WSL)

  • Cache (fast page loads)
  • Session storage (shared across servers)
  • Celery message broker

Celery (Background Worker)

  • Send order confirmation email
  • Send OTP SMS via Twilio
  • Reduce stock after order
  • Log activity to MongoDB

4. PORT MAPPING (Development vs Production)

Development Mode

Service Port Server Access URL
Customer 8000 Django runserver http://localhost:8000
Admin 8080 Django runserver http://localhost:8080
Docs 9000 Django runserver http://localhost:9000
Redis 6379 redis-server (WSL) redis://127.0.0.1:6379
MySQL 3306 mysqld (WSL) localhost:3306

Production Mode

Service Nginx (External) Gunicorn (Internal) Access URL
Customer 80 8001 http://localhost or https://xxx.ngrok-free.dev
Admin 8080 8081 http://localhost:8080 or https://xxx.ngrok-free.dev/admin-portal/
Docs 9000 9001 http://localhost:9000 or https://xxx.ngrok-free.dev/docs/
Redis - 6379 redis://127.0.0.1:6379
MySQL - 3306 localhost:3306
Why different Gunicorn ports? Nginx listens on 80, 8080, 9000. Gunicorn cannot bind to the same ports. So Gunicorn uses 8001, 8081, 9001 internally, and Nginx proxies external traffic to them.

Request Flow

User visits: https://xxx.ngrok-free.dev/accounts/auth/ | Ngrok (HTTPS) decrypts → sends HTTP to localhost:80 | Nginx (port 80) receives request — Path-Based Routing: |-- /static/ → Customer static files |-- /media/ → Customer media files |-- /admin-portal/static/ → Admin static files |-- /admin-portal/ → Strips prefix, proxies to Gunicorn Admin (8081) | Sets X-Script-Name: /admin-portal |-- /docs/static/ → Docs static files |-- /docs/ → Strips prefix, proxies to Gunicorn Docs (9001) | Sets X-Script-Name: /docs |-- / → Proxies to Gunicorn Customer (8001) | Gunicorn → Django (ScriptNameMiddleware prefixes all URLs) | Django returns HTML response → back through chain to user
Free Ngrok Limitation: URL changes every time you restart ngrok. Paid plans provide a fixed subdomain.

Example Celery Task (apps/orders/tasks.py)

from celery import shared_task
from django.core.mail import send_mail

@shared_task
def send_order_confirmation_email(order_id):
    from apps.orders.models import Order
    order = Order.objects.get(id=order_id)
    send_mail(
        subject=f'Order Confirmed - #{str(order.order_id)[:8]}',
        message=f'Thank you for your order!',
        from_email='noreply@shopease.com',
        recipient_list=[order.user.email],
    )

STEP 5 - Nginx Configuration

File: nginx_shopease.conf

# Upstream servers (Gunicorn)
upstream shopease_customer {
    server 127.0.0.1:8001;   # NOT 8000 (Nginx uses 80)
}
upstream shopease_admin {
    server 127.0.0.1:8081;   # NOT 8080 (Nginx uses 8080)
}
upstream shopease_docs {
    server 127.0.0.1:9001;   # NOT 9000 (Nginx uses 9000)
}

server {
    listen 80;
    location /static/ {
        alias "/path/to/shopease/staticfiles/";
    }
    location / {
        proxy_pass http://shopease_customer;
        proxy_set_header X-Forwarded-Proto https;  # Prevents redirect loop
    }
}

STEP 6 - Security Settings (DEBUG=False)

# shopease/config/settings/base.py
if not DEBUG:
    SECURE_SSL_REDIRECT = True
    SESSION_COOKIE_SECURE = True
    CSRF_COOKIE_SECURE = True
    SECURE_HSTS_SECONDS = 31536000
    SECURE_PROXY_SSL_HEADER = ('HTTP_X_FORWARDED_PROTO', 'https')

10. HOW EVERYTHING WORKS TOGETHER

  1. User visits Ngrok URL → Ngrok forwards to Nginx
  2. Nginx serves static files directly, proxies dynamic requests to Gunicorn
  3. Gunicorn runs Django application
  4. Django saves order → MySQL
  5. Django dispatches async task → Redis (message broker)
  6. Celery worker picks up task
  7. Celery sends confirmation email → Gmail SMTP
  8. Celery logs event → MongoDB Atlas

11. TROUBLESHOOTING

ERR_TOO_MANY_REDIRECTS (Redirect Loop)

Cause: Nginx passes X-Forwarded-Proto: http but Django has SECURE_SSL_REDIRECT=True

# Fix in nginx_shopease.conf - change in ALL server blocks:
proxy_set_header X-Forwarded-Proto https;   # NOT $scheme

502 Bad Gateway

Cause: Gunicorn is not running on the expected port

# Check Gunicorn processes
ps aux | grep gunicorn

# Restart Gunicorn
bash start_production.sh

Static Files 404 (Development)

Cause: DEBUG=False in .env

# Fix: Set DEBUG=True for development
sed -i 's/DEBUG=False/DEBUG=True/' shopease/.env

# Or just run:
bash start_all_servers.sh   # Automatically sets DEBUG=True

Static Files 404 (Production)

Cause: collectstatic not run, or Nginx config not loaded

# Collect static files
cd shopease && python manage.py collectstatic --noinput

# Reload Nginx
sudo cp nginx_shopease.conf /etc/nginx/sites-available/shopease
sudo nginx -t && sudo service nginx restart

Port Already in Use

# Stop all servers first
bash stop_all.sh

# Check what's using a port
lsof -i :8000
lsof -i :8080

Redis Connection Failed

sudo service redis-server start
redis-cli ping   # Should return PONG

MySQL Connection Failed

sudo service mysql start
mysql -u shopease_user -p   # Test login with password: prath@76

Nginx Config Error

sudo nginx -t                    # Test config syntax
sudo tail -f /var/log/nginx/error.log   # View error logs

View Gunicorn Logs

tail -f /tmp/gunicorn_customer_error.log
tail -f /tmp/gunicorn_admin_error.log
tail -f /tmp/gunicorn_docs_error.log

13.1 WSL2 (Ubuntu on Windows) — Current Setup

Pros & Cons

ProsCons
  • Full Linux environment inside Windows
  • All Linux tools work (Nginx, Gunicorn, Redis, Celery)
  • Access Windows files via /mnt/c/
  • Shares localhost with Windows (browser access)
  • VS Code WSL extension for seamless editing

13.3 macOS (Intel & Apple Silicon)

Pros & Cons

ProsCons
  • Unix-based — most Linux tools work
  • Homebrew makes installing easy
  • Good filesystem performance (APFS)
  • Bash/Zsh terminal built-in
  • VS Code, PyCharm, etc. work great
  • Gunicorn and Nginx fully supported
  • Nginx config paths differ from Linux
  • Apple Silicon (M1/M2/M3) may have pip build issues
  • No systemctl — use brew services or launchctl
  • Must update all paths in scripts and configs
  • MySQL may conflict with MariaDB from Homebrew
  • start_production.sh uses sudo service — must modify for macOS

13.4 Windows (Native — No WSL)

Pros & Cons

ProsCons
  • Familiar Windows environment
  • Django runserver works fine
  • MySQL Installer is user-friendly (GUI)
  • VS Code and PyCharm work natively
  • Good for basic development and learning
  • No Gunicorn (Unix-only, uses fork())
  • No native Nginx (third-party Windows builds are outdated)
  • No native Redis (requires Memurai or Docker)
  • Celery has limited support (no fork, must use -P solo or -P threads)
  • Bash scripts (.sh) don't run — need Git Bash or PowerShell alternatives
  • Path separator issues (\ vs /)
  • Cannot run the full production architecture
  • File permissions work differently

Production Setup

Production is NOT supported on native Windows. Gunicorn requires Unix fork() system call which Windows does not have. Nginx has unofficial Windows builds but they are outdated and lack features.

Alternatives for Production on Windows:

AlternativeEffortDescription
WSL2 (Recommended) Low Install WSL2 with Ubuntu. Full Linux environment inside Windows. All ShopEase production scripts work. See Section 13.1.
Docker Desktop Medium Containerize with Docker Compose. Requires writing Dockerfile and docker-compose.yml. Runs Linux containers on Windows.
Cloud VPS (AWS, DigitalOcean) Medium Deploy to a Linux VPS. Best for real production. Follow Native Linux (Section 13.2) on the server.
Waitress (Python WSGI server) Low Windows-compatible WSGI server. No Nginx or multi-worker support. Only for testing, NOT real production.

Waitress (Quick Windows-only workaround — NOT recommended for real production):

# Install Waitress (Windows-compatible WSGI server)
pip install waitress

# Run Customer server:
waitress-serve --host=127.0.0.1 --port=8001 config.wsgi_customer:application

# Run Admin server (another terminal):
waitress-serve --host=127.0.0.1 --port=8081 config.wsgi_admin:application

# Run Docs server (another terminal):
cd ..\shopeasedocs
waitress-serve --host=127.0.0.1 --port=9001 shopeasedocs.wsgi:application

# Ngrok (if installed):
ngrok http 8001   # Only Customer, no path-based routing without Nginx
